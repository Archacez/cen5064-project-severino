# ADR-001: Categorize transactions with keyword/merchant rules, not machine learning

**Date:** 2026-10-11 
**Status:** accepted

## Context

Each imported transaction needs a category. This is a solo, one-semester project graded on design rather than model accuracy, and I have no labeled data of my own to train a classifier on. The realistic options were keyword/merchant rules, a machine-learning classifier, or manual tagging only.

## Decision

Use keyword/merchant rules in the domain class TransactionCategorization, behind one method, categorize(transaction), with an "Uncategorized" fallback.

## Consequences

Results are deterministic, easy to unit test and explainable, with no training data needed. Unknown or ambiguous merchants (like "AMAZON") will land in "Uncategorized" or be wrong, the rule list needs maintenance, and matching must ignore case because the same merchant already appears as "Starbucks" and "STARBUCKS". The categorizer is injected into TransactionImportService, so an ML version could replace it later without touching the Service or Presentation tiers. I would revisit this if too many transactions end up Uncategorized to be useful.
