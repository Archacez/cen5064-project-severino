# ADR-002: Business rules live in the Domain; pandas only parses and cleans

**Date:** 2026-10-11
**Status:** accepted

## Context

My first import code checked validity (positive amount, non-empty merchant, real date) in TransactionImportService, once for manual entry and once as a pandas filter for CSV rows. Reviewing that AI-generated code showed the two copies could drift apart and that Transaction(-5, "", "garbage") was a legal object, even though my tier table says the Domain owns business rules.

## Decision

Move the rules into the Transaction constructor, so every input path is accepted or rejected by trying to build a Transaction, and keep pandas only for reading and cleaning the CSV.

## Consequences

There is one rule set for manual entry, CSV rows and rows read back from the database, and the rules can be unit tested without a service or a database. The costs are that attributes can still be reassigned after construction (the categorizer needs to set category), CSV rows are checked one at a time, and tightening the rules later could make old stored rows fail to load. I would revisit this if validation needs to report every problem in a row instead of stopping at the first.
